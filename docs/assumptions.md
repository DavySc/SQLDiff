# Assumptions

Generated from `crates/sqldiff-core/profiles/assumptions.toml`; do not edit. After changing the registry run `SQLDIFF_BLESS=1 cargo test -p sqldiff-core --test assumptions`.

Every `ASM-*` id SQLDiff can report (docs/verified-conversion.md, C0 item 7). The test that regenerates this file also scans the sources and fails when an id is used but not registered, registered but not used, or used in a file its entry does not list. A report shows the emitting rule's own text; the statement here is the assumption in one line.

An id `ASM-NAME:qualifier` is an instance of `ASM-NAME` (binding assumptions name the object). `ASM-NAME-*` is a family whose rest the code builds; an id registered as is wins over a family it also matches.

## What discharges an assumption

| Discharge | Meaning | Ids |
|---|---|---|
| `catalog` | A fact a catalog snapshot holds: keys, types, collation, triggers, routines | 57 |
| `generated` | Code the converter or the generator writes: a constraint, a cast, the converted callee, the woven instances | 21 |
| `deployment` | A declaration about the deployment no artifact shows: callers, sessions, data | 106 |
| `nothing` | None of these: a vendor fact still to verify, an engine limit, or a per-routine review. A deployment profile cannot accept it | 29 |
| | Total | 213 |

A deployment profile (`[deployment] accept`, docs/packs-and-config.md) may accept any id whose discharge is not `nothing`. Accepting does not change a verdict: the unit stays "equal under assumptions" and the report names the profile that accepted each assumption.
